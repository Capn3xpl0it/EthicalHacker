# 10.2.7 - Herramientas Comunes para la Evasión
En un compromiso de prueba de penetración, generalmente desea mantener el sigilo e intentar evadir y eludir los controles de seguridad que la organización pueda tener. Se pueden utilizar varias técnicas y herramientas para la evasión, incluidas las siguientes:<br>
+ Veil
+ Tor
+ Cadenas de proxy
+ Cifrado
+ Encapsulación y tunelización mediante DNS y protocolos como NTP

### Veil
__[Veil](https://github.com/Veil-Framework/Veil)__ es un marco que se puede usar con Metasploit para evadir los controles de antivirus y otros controles de seguridad. A continuación, un ejemplo de Veil:<br>
#### Paso 1. Iniciar Veil
Ejecutar el comando `veil`. Después, se muestra el menú Veil.<br>
#### Paso 2. Seleccionar evasión
Para usar Veil para la evasión, seleccione la primera opción (número 1). Veil luego muestra las cargas útiles disponibles y los comando de Veil.<br>
#### Paso 3. Enumerar las cargas útiles
Para enumerar las cargas útiles disponibles, utilice el comando `list`.<br>
#### Paso 4. Instalar una carga útil
Como ejemplo, se utilizará la carga útil de TCP inverso de Meterpreter. Después de seleccionar la carga útil, debe configurar el host local (LHOST) y luego usar el comando `generate` para generar la carga útil.<br>
#### Verificar la ubicación del archivo de carga útil
Una vez generada la carga útil, se muestra otra pantalla. En la cual, se enumeran las ubicaciones del ejecutable de la carga útil, el código fuente y el archivo de recursos de Metasploit.<br>

### Tor

Muchas personas usan herramientas como Tor para la privacidad. Tor es una herramienta gratuita que permite a sus usuarios navegar por la web de forma anónima. Tor funciona "enrutando" el tráfico IP a través de una red mundial gratuita que consta de miles de retransmisiones Tor. Cambia constantemente la forma en que enruta el tráfico para ocultar la ubicación de un usuario a cualquier persona que monitoree la red. El nombre de Tor es un acrónimo del nombre del proyecto de software original, "The Onion Router".<br>

__NOTA__: Algunos tipos de malware usan Tor para cubrir sus rastros.<br>

Tor permite a los usuarios evadir y eludir el monitoreo y los controles de seguridad porque es difícil atribuir y rastrear el tráfico hasta el usuario. Su “onion routing” (o "enrutamiento cebolla") se logra mediante el cifrado de la capa de aplicación de una pila de protocolos de comunicación que está "anidada" de manera muy similar a las capas de una cebolla. El cliente Tor cifra los datos varias veces y los envía a través de una red o circuito que incluye relés Tor seleccionados al azar. Cada uno de los relés descifra una capa de la cebolla para revelar solo el siguiente relé para que los datos cifrados restantes puedan enrutarse.<br>

__CONSEJO__: Un nodo de salida de Tor es básicamente el último nodo de Tor, o la "puerta de enlace" por donde el tráfico cifrado de Tor "sale" a Internet. Se puede apuntar a un nodo de salida de Tor para monitorear el tráfico de Tor. Muchas organizaciones bloquean los nodos de salida de Tor en su entorno. El proyecto Tor tiene una lista dinámica de nodos de salida de Tor que facilita un poco esta tarea.<br>

### Cadenas de proxy

Las [Cadenas de Proxy o Proxychains](https://github.com/haad/proxychains)__ se pueden utilizar para la evasión, ya que es una herramienta que fuerza a cualquier conexión TCP realizada por una aplicación específica a utilizar Tor o cualquier otro proxy SOCKS4, SOCKS5, HTTP o HTTPS.

### Encriptación o Cifrado
El cifrado tiene grandes beneficios para la seguridad y la privacidad, pero el mundo de la respuesta ante incidentes y el análisis forense pueden presentar varios desafíos. Incluso los organismos encargados de hacer cumplir la ley han quedado fascinados con la naturaleza de doble uso del cifrado. Al proteger la información y las comunicaciones, el cifrado tiene numerosos beneficios para todos, desde gobiernos y fuerzas armadas hasta corporaciones e individuos. Por otro lado, los agentes de amenazas pueden utilizar esos mismos mecanismos como método de evasión y ofuscación. Históricamente, incluso los gobiernos han intentado regular el uso y la exportación de tecnologías de cifrado. Un buen ejemplo es el Arreglo de Wassenaar, que es un acuerdo multinacional cuyo objetivo es regular la exportación de tecnologías como el cifrado.<br>

Como otro ejemplo, la Oficina Federal de Investigaciones (FBI) de los Estados Unidos han intentado obligar a los proveedores a dejar ciertas técnicas de investigación en su software y dispositivos. Otro ejemplo es la supuesta puerta trasera de la Agencia de Seguridad Nacional de los Estados Unidos (NSA) en el generador de bits aleatorios deterministas de curva elíptica dual (Dual_EC_DRBG), que permite la extracción de texto plano de cualquier algoritmo generado por este generador de números pseudoaleatorios.<br>

Algunas personas han comprado la idea de "cifrar todo". Sin embargo, cifrar todo tendría consecuencias muy graves, no solo para las agencias de aplicación de la ley, sino también para los profesionales de respuesta a incidentes. Algo para recordar sobre el concepto de "cifrar todo" es que la implementación del cifrado de extremo a extremo es difícil y puede dejar los datos sin cifrar en riesgo de ataque.<br>

Muchos productos de seguridad (incluidos los IPS de próxima generación y los cortafuegos de próxima generación) pueden interceptar, descifrar, inspeccionar y volver a cifrar o incluso ignorar las cargas útiles de tráfico cifrado. Algunas personas consideran que esto es un asunto en ruta (anteriormente MITM) y tienen inquietudes sobre la privacidad. Por otro lado, aún puede usar metadatos del tráfico de red y otras fuentes de eventos de seguridad para investigar y resolver problemas de seguridad. Puede obtener mucha buena información aprovechando NetFlow, los registros de cortafuego, los registros de proxy web, la información de autenticación de usuarios e incluso los datos de DNS pasivo (pDNS). En algunos casos, la combinación de estos registros puede hacer que el contenido cifrado de las cargas útiles de malware y otro tráfico sea irrelevante, si puede detectar sus patrones de tráfico para corregir un incidente.<br>

Es un hecho que debe trabajar con datos cifrados, pero debe hacerlo en tránsito o "en reposo" en un terminal o servidor. Si implementa proxies web, debe evaluar la viabilidad en su entorno de que las conexiones HTTP sean seguras contra ataques en la ruta.<br>
__CONSEJO__: Es importante reconocer que, desde la perspectiva del monitoreo de la seguridad, es técnicamente posible monitorear algunas comunicaciones cifradas. Sin embargo, desde la perspectiva de las políticas, es una tarea especialmente difícil, según su ubicación geográfica y las leyes locales relacionadas con la privacidad (por ejemplo, GDPR). Existen tecnologías como el Análisis de Tráfico Cifrado (ETA) de Cisco que pueden detectar actividades maliciosas (comportamiento de malware) sin la necesidad de descifrar paquetes.<br>

### Encapsulación y Tunelización mediante DNS y protocolos como NTP
Los actores de amenazas han utilizado muchas técnicas no tradicionales diferentes para robar datos de redes corporativas sin ser detectados. Por ejemplo, han enviado datos de tarjetas de crédito robadas, propiedad intelectual y documentos confidenciales a través de DNS mediante túneles. Como probablemente sepa, el DNS es un protocolo que permite a los sistemas resolver nombres de dominio en direcciones IP. El DNS no está diseñado para un canal de comando ni para túneles. Sin embargo, los atacantes han desarrollado un software que permite la tunelización a través del DNS. A estos agentes de amenazas les gusta utilizar protocolos que no están diseñados para la transferencia de datos porque están menos inspeccionados en términos de monitoreo de seguridad. La tunelización de DNS no detectada, presenta un riesgo significativo para cualquier organización.<br>

En muchos casos, el malware utiliza la codificación Base64 para colocar datos confidenciales (como números de tarjetas de crédito e información de identificación personal) en la carga útil de los paquetes DNS para los ciberdelincuentes. Los siguientes son algunos ejemplos de métodos de codificación que pueden utilizar los atacantes:<br>

+ Codificación Base64
+ Codificación binaria (8 bits)
+ Codificación NetBIOS
+ Codificación hexadecimal

Se han creado varias utilidades para realizar túneles DNS (tanto por buenas razones como dañinas) Los siguientes son algunos ejemplos:<br>

+ __[DeNiSe](https://github.com/mdornseif/DeNiSe)__. Esta herramienta de Python es para tunelizar TCP sobre DNS.
+ __[dns2tcp](https://github.com/alex-sector/dns2tcp)__. Escrito por Olivier Dembour y Nicolas Collignon en C, dns2tcp admite tipos de solicitudes KEY y TXT.
+ __[DNScapy](https://github.com/FedericoCeratto/dnscapy)__. Creada por Pierre Bienaimé, esta herramienta Scapy basada en Python para la generación de paquetes incluso admite túneles SSH sobre DNS, incluido un proxy SOCKS.
+ __[DNScat/DNScat-P](https://github.com/iagox86/dnscat2)__. Esta herramienta basada en Java, creada por Tadeusz Pietraszek, admite la comunicación bidireccional a través de DNS.
+ __[DNScat2 (DNScat-B)](https://github.com/iagox86/dnscat2)__. Escrita por Ron Bowes, esta herramienta se ejecuta en Linux, MacOS y Windows. Codifica las solicitudes de DNS en codificación NetBIOS o codificación hexadecimal.
+ __[Heyoka](http://heyoka.sourceforge.net/)__. Esta herramienta basada en Windows escrita en C admite la tunelización bidireccional para la exfiltración de datos.
+ __[iodine](https://code.kryo.se/iodine/)__. Escrito por Bjorn Andersson y Erik Ekman en C, iodine se ejecuta en Linux, MacOS y Windows, e incluso se puede portar a Android.
+ __[SODS](https://github.com/msantos/sods)__. Escrita originalmente en Perl por Dan Kaminsky, esta herramienta se usa para configurar un túnel SSH a través de DNS o para la transferencia de archivos. Las solicitudes están codificadas en Base32 y las respuestas son registros TXT codificados en Base64.
+ __[psudp](https://pdfs.semanticscholar.org/0e28/637370748803bcefa5b89ce8b48cf0422adc.pdf)__. Desarrollada por Kenton Born, esta herramienta inyecta datos en solicitudes de DNS existentes modificando las longitudes de los encabezados IP/UDP.
+ __[Feederbot y Moto](https://chrisdietri.ch/post/feederbot-botnet-using-dns-command-and-control/)__. Los atacantes han utilizado este malware con DNS para robar información confidencial de muchas organizaciones.

Algunas de estas herramientas no se crearon para robar datos, pero los delincuentes se han apropiado para sus propios fines.<br>
